# 📌 문제: 다중 유저 API 슬라이딩 윈도우 로그 제어
당신은 사내 결제 API 게이트웨이의 트래픽 제어 모듈을 개발하고 있습니다. 유저별로 API 호출 횟수를 엄격하게 제한하기 위해, 유저의 요청이 들어온 정확한 시간을 기록하고 검사하는 '슬라이딩 윈도우 로그' 방식을 채택했습니다.
윈도우 크기 W(초), 윈도우 내 최대 허용 요청 수 limit, 그리고 실시간으로 들어오는 유저들의 API 요청 로그 logs가 주어집니다. 각 요청에 대해 승인되면 "ACCEPT", 거절되면 "DROP"을 배열에 담아 반환하는 함수를 완성하세요.

## ⏱️ 슬라이딩 윈도우 로그 동작 규칙
- logs의 각 요소는 "요청시간 유저ID" 형태의 문자열이며, 요청 시간 기준 오름차순으로 주어집니다.- 특정 유저의 요청이 시간 T에 들어왔을 때, 해당 유저의 윈도우 범위는 [T - W + 1, T] 가 됩니다.
  - 예: W = 10이고 현재 시간이 T = 15라면, 6초 ~ 15초 사이에 승인(ACCEPT)된 요청이 몇 개인지 셉니다.
- 윈도우 범위 내에 있는 해당 유저의 승인된 요청 개수가 limit 미만이면 현재 요청을 "ACCEPT" 처리하고 로그에 기록합니다.
- limit 이상이면 현재 요청을 "DROP" 처리합니다. (DROP된 요청은 윈도우 로그에 기록되지 않으며, 이후의 요청 횟수 계산에 영향을 주지 않습니다.)

## 제한사항
- W는 1 이상 10,000 이하의 자연수입니다.
- limit는 1 이상 1,000 이하의 자연수입니다.
- logs의 길이는 1 이상 100,000 이하입니다.시간은 1 이상 1,000,000,000 이하의 자연수이며, 동일한 시간에 여러 요청이 들어올 수 있습니다.
- 유저 ID는 소문자와 숫자로 이루어진 길이 1~10의 문자열입니다.

## 입출력 예시
| W | limit | logs | result |
|---|---|---|---|
| `10` | `3` | `["1 u1", "5 u1", "10 u1", "11 u1", "12 u1", "15 u1"]` | `["ACCEPT", "ACCEPT", "ACCEPT", "ACCEPT", "DROP", "ACCEPT"]` |
| `5` | `2` | `["1 a", "2 a", "3 b", "4 a", "5 b", "6 a"]` | `["ACCEPT", "ACCEPT", "ACCEPT", "DROP", "ACCEPT", "ACCEPT"]` |


#### 예시 1번 설명 (W=10, limit=3):
- T=1: 윈도우 범위 밖 기록 없음. 큐: [1] $\rightarrow$ ACCEPT
- T=5: 큐: [1, 5] $\rightarrow$ ACCEPT
- T=10: 큐: [1, 5, 10]. 크기가 3이므로 꽉 참 $\rightarrow$ ACCEPT
- T=11: 윈도우 [2, 11]. 범위 밖인 1 제거. 큐: [5, 10]. 2개 있으므로 허용 $\rightarrow$ ACCEPT (큐: [5, 10, 11])
- T=12: 윈도우 [3, 12]. 범위 밖 기록 없음. 큐: [5, 10, 11]. 크기가 3(제한)이므로 차단 $\rightarrow$ DROP (차단되었으므로 큐에 12를 넣지 않음)
- T=15: 윈도우 [6, 15]. 범위 밖인 5, 10 제거. 큐: [11]. 1개 있으므로 허용 $\rightarrow$ ACCEPT (큐: [11, 15])
