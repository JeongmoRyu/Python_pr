# 📌 문제: 분산 Key-Value 저장소 스냅샷 생성기
당신은 인메모리 Key-Value 저장소의 데이터 정합성을 관리하는 백엔드 엔지니어입니다. 이 저장소는 모든 데이터 변경 작업을 Append-Only 형태의 로그로만 순차적으로 기록합니다. 메모리 낭비를 막기 위해, 당신은 정기적으로 이 로그들을 읽어 최종적으로 유효한 데이터만 남기는 스냅샷(Snapshot)을 만들어야 합니다.
로그 기록이 담긴 배열 logs와 스냅샷을 생성하는 현재 시간 current_time이 주어질 때, 아래의 규칙에 따라 최종적으로 저장소에 남아있는 데이터들을 "키 값" 형태의 문자열 배열로 만들어 키(Key) 기준 사전 오름차순으로 반환하는 함수를 완성하세요.

## 💾 로그 처리 및 만료(TTL) 규칙
- logs의 각 요소는 공백으로 구분된 문자열이며, 시간(T) 기준 오름차순으로 주어집니다.
- T PUT key value: 특정 key에 value를 저장합니다. 이 데이터는 영구적으로 유지됩니다.
- 만약 이미 존재하는 key라면 새로운 value와 만료 정책으로 완전히 덮어씁니다.
- T PUT key value TTL: 특정 key에 value를 저장하지만, 이 데이터는 T + TTL 시점에 만료됩니다.
  - 스냅샷을 생성하는 current_time이 T + TTL 이상(크거나 같음)이라면, 이 데이터는 만료되어 삭제된 것으로 간주합니다.
- T DELETE key: 특정 key의 데이터를 즉시 삭제합니다.

## 제한사항
- logs의 길이는 1 이상 100,000 이하입니다.
- current_time과 T, TTL은 1 이상 1,000,000,000 이하의 자연수입니다.
- key와 value는 알파벳 소문자와 숫자로 이루어진 길이 1~10의 문자열입니다.
- 최종 스냅샷에 남은 데이터가 없다면 빈 배열 []을 반환합니다.

## 입출력 예시

| logs | current_time | result |
|---|---|---|
| `["1 PUT a 10", "2 PUT b 20 3", "3 DELETE a", "4 PUT c 30 5"]` | `5` | `["c 30"]` |
| `["10 PUT s1 tA 50", "20 PUT s2 tB", "30 PUT s1 tC", "40 DELETE s2"]` | `50` | `["s1 tC"]` |

#### 예시 1번 설명:
- T=1: a에 10 저장 (영구)
- T=2: b에 20 저장 (만료 시간: 2 + 3 = 5)
- T=3: a 삭제
- T=4: c에 30 저장 (만료 시간: 4 + 5 = 9)
- 스냅샷 생성 (current_time = 5):
  - a: T=3에 삭제됨.
  - b: 만료 시간이 5이므로, 현재 시간 5에서 만료되어 삭제 처리됨.
  - c: 만료 시간이 9이므로 현재 유효함.
- 결과: ["c 30"]
