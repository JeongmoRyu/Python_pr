# 📌 문제: AI API 게이트웨이 토큰 버킷 구현
당신은 사내 AI 서비스의 트래픽을 제어하는 게이트웨이 담당자입니다. 과도한 API 호출로 인해 GPU 서버가 다운되는 것을 막기 위해, 사용자 요청을 필터링하는 토큰 버킷(Token Bucket) 방식의 Rate Limiter를 구현하려고 합니다.
버킷의 최대 용량 capacity, 초당 충전되는 토큰 수 refill_rate, 그리고 사용자의 API 요청 기록이 담긴 배열 requests가 주어질 때, 각 요청이 승인되었는지( "200" ) 거절되었는지( "429" )를 배열에 담아 반환하는 함수를 완성하세요.

## 토큰 버킷 동작 규칙
- requests의 각 요소는 [요청 시간(초), 필요한 토큰 수] 형태의 정수 배열입니다. (요청 시간은 오름차순으로 주어집니다.)
- 초기 상태: 서버가 시작되는 시간(T=0)에 버킷은 최대 용량인 capacity만큼의 토큰이 가득 차 있습니다.
- 토큰 충전: 시간이 흐름에 따라 1초당 refill_rate만큼의 토큰이 버킷에 추가됩니다.
  - 단, 버킷의 토큰 수는 최대 용량(capacity)을 초과할 수 없습니다.
  - 예: 이전 요청이 T=1이고 현재 요청이 T=4라면, 3초가 흘렀으므로 3 × refill_rate만큼의 토큰이 충전됩니다.
- 요청 처리:
  - 충전이 먼저 이루어진 후, 버킷에 있는 토큰 수가 요청한 토큰 수 이상이라면, 요청한 만큼 토큰을 차감하고 "200"(승인)을 반환합니다.
  - 버킷에 토큰이 부족하다면, 토큰을 전혀 차감하지 않고 "429"(Too Many Requests / 거절)를 반환합니다.
  
## 제한사항
= capacity는 1 이상 1,000,000 이하의 자연수입니다.
- refill_rate는 1 이상 100,000 이하의 자연수입니다.
- requests의 길이는 1 이상 100,000 이하입니다.
- 요청 시간은 1 이상 1,000,000,000 이하이며, 동일한 시간에 여러 요청이 들어올 수도 있습니다.

## 입출력 예시
| capacity | refill_rate | requests | result |
|---|---|---|---|
| `10` | `2` | `[[1, 5], [1, 6], [2, 3], [5, 10]]` | `["200", "429", "200", "200"]` |
| `5` | `1` | `[[2, 5], [3, 2], [10, 5]]` | `["200", "429", "200"]` |

#### 예시 1번 설명:
- T=0: 초기 버킷 상태 = 10개
- T=1 (5개 요청): 1초 경과 $\rightarrow$ 2개 충전 (최대 10개로 제한). 10개 중 5개 사용 $\rightarrow$ 남은 토큰 5개 ("200")
- T=1 (6개 요청): 0초 경과 $\rightarrow$ 0개 충전. 현재 5개인데 6개를 요구하므로 부족 $\rightarrow$ 차감 없이 거절 ("429")
- T=2 (3개 요청): 1초 경과 $\rightarrow$ 2개 충전. 현재 7개(5+2). 3개 사용 $\rightarrow$ 남은 토큰 4개 ("200")
- T=5 (10개 요청): 3초 경과 $\rightarrow$ 6개 충전. 최대 10개로 제한(4+6). 10개 사용 $\rightarrow$ 남은 토큰 0개 ("200")
